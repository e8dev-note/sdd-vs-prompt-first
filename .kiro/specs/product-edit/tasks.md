# Implementation Plan

- [ ] 1. 基盤: 入力検証と更新
- [ ] 1.1 商品入力の検証関数を実装する
  - フォーム由来の文字列(null 含む)を受け取り、name / category は前後の空白を除いて必須、price は 0 以上の 10 進整数(安全な範囲)、note は空なら未設定として正規化する
  - 不正な項目を全て同時に返す。メッセージは name / category「必須です」、price「0 以上の整数で入力してください」
  - テスト: 空・空白のみ・前後空白付き、price の空 / 小数 / 負数 / 文字列 / 指数表記 / 0 / 先頭ゼロ / 前後空白、note の空と空白、複数エラーの同時返却
  - 完了状態: 上記テストが通り、関数は DB・React に依存しない
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.7, 3.3, 5.1_

- [ ] 1.2 商品の更新をリポジトリに追加する
  - 検証済み入力で name / category / price / note と updated_at(保存時刻)を更新し、更新後の行を返す
  - 影響行数 0(削除済み)なら null を返す。id / code / created_at は変更しない
  - テスト: 値と updated_at が更新される(created_at より後)、code と created_at が不変、不在で null、更新後の一覧・検索で新しい値が出る
  - 完了状態: 上記テストが通り、既存テストも通る
  - _Requirements: 3.1, 3.4, 3.5, 3.7, 5.1_

- [ ] 2. コア: Server Action
- [ ] 2.1 更新の Server Action を追加する
  - 前回状態と FormData を受け取り、id の解析 → 検証 → 更新の順で処理し、結果を状態として返す(例外や redirect は使わない)
  - 検証エラーは項目ごとのエラー、不在・不正 id はフォーム全体のエラーとして返す
  - 成功時は詳細ページと一覧を再検証し、保存時刻を含む成功状態を返す
  - 完了状態: 不正な FormData で項目エラーが返り、正しい FormData で DB が更新され成功状態が返る(手動 curl または後続の E2E で確認)
  - _Requirements: 2.6, 3.2, 3.5, 3.7_

- [ ] 3. コア: 画面
- [ ] 3.1 編集モーダル部品を実装する
  - 「編集」ボタンとネイティブ dialog。開くときに商品の現在値で入力状態を初期化し、モーダル表示で開く(背後は操作不可)
  - name / category / price / note を制御コンポーネントで持ち、code は読み取り専用で表示。最初の入力欄に自動フォーカス
  - 送信は Server Action。項目エラーは各入力欄の直下に、全体エラーはフォーム上部に表示。エラー時も入力値は残る
  - 保存中は保存ボタンを無効化。成功状態(保存時刻の変化)を検知したらモーダルを閉じる
  - キャンセルボタンと Esc(dialog の close)で入力状態を商品の値に戻す
  - 完了状態: 単体で描画でき、上記の開閉・表示・エラー・pending の挙動を持つ
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 1.6, 2.5, 3.2, 3.6, 4.1, 4.2, 4.3, 4.4_

- [ ] 4. 統合と完了条件
- [ ] 4.1 詳細画面に編集モーダルを配置する
  - 削除ボタンの横に編集ボタン(モーダル)を置く。既存の表示・導線・削除は変更しない
  - 完了状態: 詳細画面に「編集」ボタンが出て、押すとモーダルが開く
  - _Requirements: 1.1_

- [ ] 4.2 完了条件を検証する
  - `npm run build`、`npm run lint`、`npm test` を全て通す
  - ブラウザで: 編集 → 現在値が入っている → name を空、price を `abc` にして保存 → 両方のエラーが出て入力値が残る → 修正して保存 → モーダルが閉じ、詳細の値と updated_at が変わる → 一覧でも新しい値 → 再度開いて変更しキャンセル → 値が戻る → Esc でも同様
  - 完了状態: 3 コマンドが成功し、上記の流れが動く
  - _Requirements: 5.1, 5.2_
